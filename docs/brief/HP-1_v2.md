# 実装プロンプト 指示書 HP-1 v2：株式会社野田 公式サイト 完全リニューアル

## 0. 前提

### 0-1. 目的
現行サイト https://duct-noda.com/（WordPress + Elementor）を廃止し、同じドメインで新サイトを **PHP + MySQL の自作構成** で作り直す。見やすさ・文章構成・検索での見つかりやすさ・管理のしやすさを上げる。デザインは「白×青×オレンジ、左カラム固定、ゴシック体、控えめなアニメーション」。

### 0-2. 役割
- ボス：発注者。判断・確認・画像の用意・サーバーへのアップロードを行う。技術者ではないので、報告・ドキュメントは専門用語を避けて書く。
- 実装役（あなた）：この文書どおりに設計・実装・試験・ドキュメント作成を行う。

### 0-3. 動作環境（本番）
- レンタルサーバー：コアサーバー（CORESERVER）。PHP 8.x、MySQL（MariaDB）、Apache（.htaccess 有効）。SSH は使わない前提。ボスが FTP でアップロードする。
- ドメイン：duct-noda.com（変更なし）。HTTPS。
- 外部の有料サービス、ビルドが必要な仕組み（Node でのビルド等）は使わない。実装役の手元で生成したファイルをそのまま置けば動く形にする。

### 0-4. 開発環境（実装役の手元）
- PHP 8.2 以上、MySQL 8 または MariaDB 10.6 以上（Docker 可）。
- `php -S` の内蔵サーバーで動作確認できること。
- git で管理する（リポジトリ名 `noda-site`）。コミットは実装役が行う。

### 0-5. 渡される資料
- `design/top-reference.html`：**トップページの見本（確定デザイン・案C）。** ブラウザで開ける1枚のHTML。構成・各部の寸法・色・文言・動きの基準はこのファイル。写真は現行サイトから直接読み込んでいる。本文2章の数値指定と食い違う場合は2章を優先し、食い違いを報告する。スマホ表示はこの見本にないので2-4に従う。
- `migration/WordPress_2026-10-21.xml`：現行サイトの書き出しファイル（公開記事168件、下書き「テンプレ」5件、添付画像167件の情報）。
- 現行サイトは公開中。画像は `https://duct-noda.com/wp-content/uploads/...` から直接取得してよい。記事データは `https://duct-noda.com/wp-json/wp/v2/posts` からも取得できる。プライバシーポリシーの本文は `https://duct-noda.com/privacypolicy/` から取得する。
- 画像（生成・実物）：ボスが後日 `images/` フォルダで渡す（ファイル名は付録C）。**届く前に実装を進める。** 未着の画像は「灰色の枠＋ファイル名」で仮置きし、ファイルを置けば自動で表示される。

### 0-6. 用語
- 施工事例：工事の実績記事。管理ページから投稿する。
- お知らせ：トップの「お知らせ」欄。施工事例の新着と、告知（休業など）の両方が混ざって新しい順に出る。
- 業態：店の種類（焼肉店など）のカテゴリ軸。
- 工事の種類：工事内容（厨房フードなど）のカテゴリ軸。
- 左カラム：全ページ共通の左側の縦メニュー。
- 管理ページ：`/admin/` 以下のログインが必要な画面。
- 試験用の場所：本番サーバーの `https://duct-noda.com/new/`。公開前の確認に使う。

### 0-7. 完走規則
- 9章の順に進め、各「停止点」でボスに報告し、返事を待つ。停止点以外で止まらない。
- 軽い不備（引数の渡し忘れ、試験用データの不足、設定の書き漏れなど、仕様・期待値を変えずに直せるもの）は、停止・裁定を求めずに自力で直して進める。
- 仕様が矛盾している・この文書に書いていない判断が必要な場合だけ、停止点を待たずに「選択肢と推奨」を添えてボスに質問する。質問は1回にまとめる。
- 事実（会社情報・数字・固有名詞）は付録Aと付録Bにあるものだけを使う。無い事実を作らない。

### 2-7. アニメーション（控えめ、性能に影響しない範囲）
- 表示時のふわっと上がる動き：各セクションの直下の要素に、画面内に入った時 1 回だけ（IntersectionObserver）。移動 16px、0.7秒、`cubic-bezier(.2,.7,.2,1)`。同一セクション内の兄弟は 0.08秒ずつ遅らせる（最大 4 つまで）。
- 最初の画面の写真：18秒かけて 1.0→1.07 倍、往復、無限。
- 流れる帯：CSS の `transform` だけで 38秒 1 周、無限。内容を2回並べて途切れなくし、2回目は `aria-hidden="true"`。
- ホバー：2-6 のとおり。
- `prefers-reduced-motion: reduce` の時は全て無効。
- JS でのアニメーションライブラリは使わない。CSS と IntersectionObserver のみ。レイアウトのずれ（CLS）を起こさない（`opacity` と `transform` だけ動かす）。

### 2-8. 性能・検索対策・計測の目標（数値）
- Lighthouse（モバイル）：性能 90 以上、アクセシビリティ 95 以上、SEO 95 以上、ベストプラクティス 90 以上。トップ・施工事例一覧・施工事例詳細・サービス1ページで計測。
- CSS 合計 60KB 以下、JS 合計 40KB 以下（gzip前、外部ライブラリ含まず。管理ページは除外）。
- 画像：`loading="lazy"`（最初の画面の写真だけ `fetchpriority="high"` で先読み）、`width`/`height` 属性必須、WebP を `<picture>` で出し JPG を代替に。公開画像は長辺 1600px 以下、一覧用サムネイルは 800px 幅を別に作る。
- 全ページ：`<title>`、`meta description`、`canonical`、OGP（`og:title/description/image/url/type`）、`twitter:card`。施工事例詳細の OGP 画像は代表写真、それ以外は `og-default.jpg`。
- 構造化データ（JSON-LD）：全ページ Organization + BreadcrumbList。トップは LocalBusiness（住所・電話・営業時間）。よくある質問は FAQPage。施工事例詳細は Article（見出し・画像・公開日）。
- `sitemap.xml` は固定ページ＋公開中の施工事例＋お知らせを自動生成。`robots.txt` は `/admin/` を Disallow。
- 計測タグ：現行サイトの Google タグマネージャー（コンテナ ID `GTM-N3DNWHNN`）を全公開ページに入れる（管理ページには入れない）。設定ファイルで ID を変えられるようにする。

### 3-2. カテゴリの初期データ（付録B）を投入する。

### 3-3. 現行サイトからの移行（スクリプト `migration/migrate.php`。何度実行しても同じ結果になるようにする）
1. `migration/WordPress_2026-10-21.xml` を読む。`post_type=post` かつ `status=publish` の 168 件だけ対象。題名「テンプレ」は除外。
2. slug：XML の `post_name` を URL デコードして保存。公開URLが現行と完全に一致すること。
3. 本文：WordPress のブロックコメント（`<!-- wp:... -->`）を除去。残す要素は `p, h2〜h4, ul, ol, li, strong, em, a, br` のみ。`h5/h6` は `h3` に、`h1` は `h2` に変換。`div, span, style, class 属性, インラインstyle` は除去。空の段落は削除。
4. 本文中の `<img>` は本文から取り除き、`case_images` に順番どおり登録する（本文は文字だけ、写真は本文下のギャラリー）。アイキャッチ（`_thumbnail_id` の添付）を先頭にし、`thumbnail_image_id` にする。重複する画像URLは1枚にまとめる。
5. 画像ファイルは `https://duct-noda.com/wp-content/uploads/...` からダウンロードし、**同じ相対パス** `public/wp-content/uploads/YYYY/MM/ファイル名` に保存（元のURLが壊れないため）。そこから長辺 1600px 版と 800px 幅サムネイル版（JPG と WebP）を `public/media/cases/<case_id>/` に生成し、`case_images.path` にはそちらを入れる。取得に失敗したものは一覧に記録して続行する。
6. 日付：`post_date` → `published_at`。
7. 検索用設定：postmeta の `_aioseo_title` → `seo_title`、`_aioseo_description` → `seo_description`。空なら title と本文冒頭 110 字から自動生成。
8. 場所（`location`）：題名から、47都道府県名・「福岡市○○区」「北九州市○○区」「広島市○○区」「○○市」「○○町」「○○郡」の順に正規表現で抽出し、最初に当たった語を入れる。例「福岡市中央区【焼き鳥店】…」→「福岡市中央区」。当たらない場合は空欄。
9. カテゴリの変換：付録Bの「旧→新 対応表」と「題名のキーワード規則」を順に適用。1件に業態 1つ以上・工事の種類 1つ以上が付くようにする。どちらかが付かない場合は、業態なら「施設・工場・その他」、工事の種類なら「換気・給気・ファン工事」を付けたうえで「要確認」フラグを立てる。
10. 移行報告 `migration/report.csv` を出力：id, 題名, 公開URL, 旧カテゴリ, 新・業態, 新・工事の種類, 場所, 画像枚数, 取得失敗画像, 要確認フラグ。UTF-8 BOM 付き（Excel で開く前提）。

### 3-4. 受け入れ条件
- 公開中 168 件が `cases` に入り、現行の URL 168 本が新サイトで全て 200 を返す。
- 画像の取得失敗が 5 枚以下（超える場合は原因を報告）。
- 要確認フラグが 30 件以下。
- `migration/report.csv` が出力されている。

## 5. 管理ページ `/admin/`

### 5-1. ログイン
- ID とパスワード。`password_hash`（bcrypt）。セッションは `HttpOnly; Secure; SameSite=Lax`、無操作 2 時間で自動ログアウト。5 回失敗で 15 分ロック。CSRF トークンを全フォームに。
- 初回セットアップ：`/admin/setup.php` をブラウザで開くとテーブル作成と最初の管理者作成を行い、完了後に自分を無効化する（ファイルを `setup.php.done` に改名）。

### 5-2. 施工事例の管理（一覧 / 新規 / 編集 / 削除）
- 一覧：題名・業態・工事・場所・投稿日・状態（公開/下書き）、題名の検索、状態の絞り込み、新しい順。1 ページ 30 件。
- 編集画面の項目：
  1. 題名（必須）
  2. 本文：見出し（H2/H3）・太字・箇条書き・リンクだけが使える簡易エディタ（自前またはライセンスが自由な軽量エディタを同梱。アカウント登録が要るサービスは不可）。保存時に 3-3-3 と同じ許可要素だけに消毒する。
  3. 写真：複数ファイルを一度に追加（ドラッグ＆ドロップとファイル選択）。並び替え（ドラッグ）、1 枚ごとに削除、代表写真（一覧用）の指定。アップロード時に長辺 1600px と 800px 幅のサムネイルを自動生成、EXIF の向きを補正、JPG と WebP を保存。1 枚 15MB まで、拡張子と MIME を検査。
  4. 場所（自由入力 1 欄、例「福岡市中央区」）
  5. 業態（チェックボックス、複数可）
  6. 工事の種類（チェックボックス、複数可）
  7. 投稿日（日付、初期値は今日。トップのお知らせの日付に使う）
  8. 状態（公開 / 下書き）
  9. 検索用の題名・説明文（任意。空なら自動生成）
  10. URL スラッグ（任意。空なら題名から自動生成。日本語可。変更時は `slug_redirects` に旧→新を記録して 301 する）
- 「保存」「保存して確認（公開画面を新しいタブで開く）」「削除（確認ダイアログ）」。
- 削除は論理削除（status=deleted）とし、一覧から消える。完全削除は不要。
- 保存後、トップの「お知らせ」と「最新の施工事例」に自動で反映される（キャッシュがある場合は消す）。

### 5-3. お知らせの管理
- 題名・本文（簡易エディタ）・投稿日・状態・スラッグ。一覧 / 新規 / 編集 / 削除。

### 5-4. カテゴリの管理
- 業態・工事の種類それぞれで、追加・名前変更・並び替え・削除（使用中は削除不可）。

### 5-5. 設定・保守
- Instagram のトークン入力欄と「接続テスト」ボタン、最終取得日時の表示。
- 管理者のパスワード変更。
- お問い合わせの受信一覧（`contact_logs`）。
- データの書き出し：施工事例・お知らせ・カテゴリを JSON 1 ファイルで書き出すボタン（画像のパス一覧を含む）。将来の引っ越しやバックアップ用。

## 6. Instagram の自動表示
- Instagram 公式の「Instagram API with Instagram Login」（Graph API）で、自アカウントの最新 6 件（画像 / 動画のサムネイル）を取得する。
- 取得は 6 時間に 1 回まで：設定に保存したトークンで取得し、結果を `storage/cache/instagram.json` に保存。公開ページはこのファイルだけを読む。取得失敗時は前回のファイルをそのまま使う。
- 長期トークン（60 日）の更新を、取得時に残り 10 日以下なら自動で行う。
- トークンが未設定・無効のときの表示：付録Cの `ig-fallback-1.jpg`〜`ig-fallback-6.jpg`＋「Instagram で見る」ボタン。
- `docs/INSTAGRAM.md` に、ボスが Meta 側で行う手順（アプリ作成 → Instagram ログインの設定 → テスターにアカウント追加 → トークン発行 → 管理ページに貼る）を、画面名を使って専門用語なしで書く。

## 7. セキュリティ
- SQL は全て PDO のプリペアドステートメント。出力は全て HTML エスケープ（本文の許可済み HTML を除く）。
- アップロード先 `public/media/` と `public/wp-content/uploads/` には `.htaccess` で PHP 実行禁止。
- 設定ファイル（DB 接続情報）は `app/config.php` に置き、`public/` の外に置けない場合は `.htaccess` で直接アクセス禁止。`config.sample.php` を同梱し、本物は git に入れない。
- HTTPS へ 301。`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: strict-origin-when-cross-origin`。
- エラー表示は本番で OFF、ログは `storage/logs/`。

## 11. 禁止
- WordPress・各種 CMS・フロントエンドのフレームワーク（React 等）・ビルド工程・有料サービス・アカウント登録が必要な外部サービスの使用。
