# 新しいホームページの置き方（ボス向け）

この手順書は2部に分かれています。

- **A. 試験用の場所（https://duct-noda.com/new/）に置く** … いま行う手順です（段階7）
- **B. 本番に切り替える** … /new/ で確認が済んでから行います

---

## A. 試験用の場所（/new/）に置く

いまの WordPress のサイトはそのまま動かしたまま、同じサーバーの中の `new` というフォルダに新しいホームページを置きます。
お客様が見る現行サイトのファイルとデータベースには触りません。/new/ は Google などの検索にも載りません。

所要時間：1時間ほど（うち半分はファイルを上げる待ち時間）

用意するもの

| もの | どこにあるか |
|---|---|
| `noda-site-1-of-9.zip` 〜 `noda-site-9-of-9.zip`（9個、合わせて約730MB）と `install.php` の、全部で10個のファイル | 私（制作側）が渡したもの。zip は広げずにそのまま使います |
| コアサーバーの管理画面に入る ID とパスワード | コアサーバーの契約時のメールなど |

> 画面の名前は、コアサーバーが時々変えます。この手順書と少し違う時は、近い名前のボタンを選んでください。分からなくなったら、画面の写真を送ってもらえれば次に押す所をお伝えします。

### 1. PHP の版を確かめる（済み）

2026-10-22 に確かめ済みです（「ドメイン別PHPバージョン」が PHP 8.2）。設定は変えずにそのまま進めてください。細かい版の数字は、手順5の終わりの画面に出ます。

### 2. データベースを作る（5分）

新しいホームページの施工事例やお問い合わせを保存する場所です。現行の WordPress のものとは別に、新しく1つ作ります。

1. 管理画面の「データベース」→「新規作成」（または「データベースの追加」）を開く
2. データベース名：`nodanew` など分かりやすい名前を入れる
3. ユーザー名とパスワードを決める（パスワードは英数字を混ぜて12文字以上）
4. 文字コードを選ぶ欄があれば `utf8mb4` を選ぶ
5. 作成する
6. 画面に出た **データベース名・ユーザー名・パスワード・ホスト名** をメモする
   - コアサーバーでは、名前の前にアカウント名が自動で付くことがあります（例：`noda_nodanew`）。メモするのは、画面に出ている付いた後の名前です
   - ホスト名は、ふつうは `localhost` です

### 3. ファイルマネージャーで new フォルダを作る（5分）

1. コアサーバーの管理画面で「ファイルマネージャー」を開く
2. **現行サイトのファイルが入っているフォルダ**を開く
   - 目印は `wp-config.php` というファイルと `wp-content` というフォルダがある所です（`public_html` や `duct-noda.com` という名前のフォルダの中にあることが多い）
3. そのフォルダの中に、新しいフォルダを作って名前を `new` にする
4. 作った `new` フォルダを開く（中は空です）

### 4. 10個のファイルを上げる（10〜30分）

1. `new` フォルダを開いたまま、アップロードのボタンで zip 9個と `install.php` の10個を選んで上げる（何回かに分けても構いません）
2. 10個すべてが `new` の中に並んだら完了です。zip の大きさ（1個約90MB）が、こちらで渡したものと同じか見比べてください
   - **zip はファイルマネージャーの「解凍」「展開」で広げないでください。** 次の手順5で自動で広げます
   - 「大きすぎる」「サイズ上限」などのエラーで上がらない時は、画面の写真を送ってください。もっと小さく分けた zip を作り直してお送りします

### 5. ファイルを広げる（5分）

1. ブラウザで **https://duct-noda.com/new/install.php** を開く
2. 「ファイルを広げています… ○%」と出て、zip を1個ずつ自動で広げていきます。閉じずに待ってください
   - 「zip が足りません」と出た時は、書かれている zip を手順4で上げてから読み込み直してください
   - 止まったように見える時は、ページを読み込み直すと続きから進みます
3. 「ファイルを広げ終わりました」と出たら、そこに書かれている「PHP の版」の数字を私に送ってから、「最初の設定へ進む」を押す
   - zip と install.php は自動で消えます

### 6. 最初の設定（5分）

**1/2 データベース**

1. 手順2でメモした、ホスト名（ふつうは `localhost` のまま）・データベース名・ユーザー名・パスワードを入れる
2. 「試しに置いている場所なので、Google などの検索に載せない」は **印を付けたまま** にする
3. 「つながるか確かめて次へ」を押す
   - ここで施工事例168件と写真1,128枚の情報が自動で入ります（数十秒かかることがあります）

**2/2 管理画面の ID とパスワード**

1. 管理画面に入るための ID（半角英数字）とパスワード（10文字以上）を決めて入れる
2. 「登録する」を押すとログイン画面に変わります。決めた ID とパスワードでログインできれば完了です
   - この ID とパスワードは手帳などに控えてください。この画面は一度しか出ません

### 7. 確かめること（停止点4）

| | やること | うまくいった時 |
|---|---|---|
| ① | パソコンとスマホで https://duct-noda.com/new/ を開き、いろいろなページを見る | 確認版と同じ見た目で、施工事例の写真も出る |
| ② | https://duct-noda.com/new/admin/ にログインし、「施工事例」→「新しく書く」で、題名・本文・写真1〜2枚・業態と工事の種類を入れて「公開する」で保存 | 「保存しました」と出て、施工事例の一覧のいちばん上に出る |
| ③ | ②の事例を開き、題名を少し直して保存 | 公開ページの題名が変わる |
| ④ | ②の事例の編集画面のいちばん下「削除する」 | 一覧から消える |
| ⑤ | https://duct-noda.com/new/contact/ から1回送信（ご自分のメールアドレスで） | 「受け付けました」の画面になり、担当の4人にメールが届き、入れたアドレスに自動返信が届く（迷惑メールのフォルダも見てください） |

気づいたこと・おかしな所は、このスレッドに画面の写真付きで送ってください。私が直して、直した一式をお渡しします。

### 8. 手直しを入れる時（2回目以降）

直したファイルだけの小さな zip（`noda-site-1-of-1.zip`）と `install.php` をお渡しします。本番に切り替えた後も同じやり方です。

1. 2つを、新しいホームページのフォルダ（切り替え前は `new`、切り替え後は `public_html`）に上げる（同じ名前があれば上書き）
2. ファイルマネージャーで `install.php` の名前を、毎回ちがう名前に変える（例：`kousin4.php`。名前はその都度お伝えします）
   - 同じ名前のままだと、サーバーが前回の「もう無いファイル」を覚えていて開けないことがあります
3. ブラウザでその名前のページを開く（例：https://duct-noda.com/new/kousin4.php ）。開けない時は数分待ってから開き直す
4. 「ファイルを広げ終わりました」と出れば完了。zip とそのファイルは自動で消えます
   - `index.php` などほかのファイルは消さないでください

### 困った時

| 出てくる文・様子 | 原因と直し方 |
|---|---|
| install.php で「サーバーの準備が足りません」 | PHP の版が古いなど。「足りません」の所を写真で送ってください（版は手順1で直せます） |
| install.php で「zip を開けません」 | その zip が途中までしか上がっていない。書かれている zip だけ手順4でもう一度上げ直し（上書き）、読み込み直す |
| 1/2 で「データベースにつながりませんでした」 | データベース名・ユーザー名のアカウント名付きの形、パスワードの打ち間違いが多いです。手順2の画面と見比べる |
| 1/2 で「データベースの場所は…」 | ホスト名は管理画面に書かれているもの（ふつうは `localhost`）を入れる |
| フォームで「送信できませんでした。お手数ですが、お電話ください」 | お問い合わせ自体は管理画面の「設定」→「受信一覧を見る」に残っています。メールの送信だけ失敗しています。私に連絡してください |
| 画面が真っ白・「エラー」とだけ出る | 私に連絡してください。ファイルマネージャーで `new/storage/logs/` の中の `php-error.log` を開いて、中身を送ってもらえると早く直せます |
| 最初からやり直したい | ファイルマネージャーで `new` フォルダを丸ごと削除し、管理画面で手順2のデータベースを削除してから、手順2からやり直す |

## B. 本番に切り替える

/new/ で確かめた新しいホームページを、https://duct-noda.com/ に切り替えます。
やることは、ファイルマネージャーで **フォルダやファイルを「移動」するだけ** です。データベースや設定はそのまま使います。
いまの WordPress のファイルは消さずに別の場所へよけておくので、うまくいかない時は元に戻せます（B-7）。

所要時間：30分ほど（ホームページが表示されない時間は、手順 B-2〜B-3 の数分だけ）
おすすめの日時：お問い合わせの少ない時間（平日の17時以降か、土日）

### B-0. 始める前に（前日まででよい）

1. /new/ に最新の手直しが入っているか確かめる（最後にお渡しした zip を入れて「ファイルを広げ終わりました」まで済んでいること）
2. ファイルマネージャーで `public_html`（`wp-admin` などがある所）を開き、**一覧の画面の写真を私に送る**
   - 写真を見て、移すもの・残すものの名前を、Boss のサーバーに合わせた一覧にしてお返しします。以下の手順はその一覧に沿って進めます
3. Google アナリティクスで数字を見ている場合は、それを設定した人に「ホームページを作り替えるので、Google タグマネージャー（GTM-N3DNWHNN）に GA4 のタグが入っているか確かめてほしい」と伝える
   - いまのサイトは WordPress の「Site Kit」という部品からも Google のタグを読み込んでいます。新しいサイトではこの部品が無くなるため、タグマネージャー側に入っていないと、切り替えの日から数字が取れなくなります

### B-1. よけておく場所を作る（2分）

1. ファイルマネージャーで `duct-noda.com` のフォルダを開く（`public_html` の **一つ上**。`logs` や `public_html` が並んでいる所）
2. 新しいフォルダを作り、名前を `wp-old` にする
   - `public_html` の **外** に作るのが大事です。外に置けば、よけたファイルがインターネットから見えません

### B-2. WordPress のファイルを `wp-old` へ移す（3分）

ここからホームページが一時的に表示されなくなります。続けて B-3 まで進めてください。

1. `public_html` を開く
2. 次のものだけに印を付けて、「移動」で `duct-noda.com/wp-old` へ移す
   - フォルダ：`wp-admin`、`wp-includes`
   - ファイル：`index.php`、`.htaccess`、`wp-` で始まるファイル全部（`wp-config.php`、`wp-login.php` など）、`xmlrpc.php`、`license.txt`、`readme.html`
3. 次のものは **移さずにそのまま** 残す
   - `new`（新しいホームページ）
   - `wp-content`（旧サイトの写真が入っています。他のサイトや Google の画像検索から写真へのリンクが切れないように残します。中のプログラムは新しいサイトの設定で動かないようにしてあります）
   - `cgi-bin`、`google` で始まるファイル（Google の持ち主確認用）、その他 B-0 の一覧で「残す」としたもの

### B-3. 新しいホームページを一番上へ移す（3分）

1. `public_html/new` を開く
2. 中身を **全部** 選んで（`.htaccess` も含む）、「移動」で `public_html` へ移す
   - 中身は `app`、`assets`、`media`、`migration`、`storage`、`vendor`、`.htaccess`、`index.php`、`robots.txt` です
3. 空になった `new` フォルダを削除する

これで切り替えは終わりです。検索に載せない設定（/new/ の時だけ）は、一番上に移ると自動で外れます。

### B-4. 確かめること（10分）

画面が変わらない時は、数分待ってからブラウザで読み込み直してください（サーバーへの反映に数分かかることがあります）。

| | 開くページ | うまくいった時 |
|---|---|---|
| ① | https://duct-noda.com/ （パソコンとスマホ） | 新しいトップページが出る。写真も出る |
| ② | https://duct-noda.com/construction_examples/ と、事例を1つ | 一覧と詳しいページが出る |
| ③ | https://duct-noda.com/category/yakiniku/ （旧サイトのアドレスの例） | 新しい施工事例の一覧へ自動で移る |
| ④ | https://duct-noda.com/admin/ | ログイン画面が出る。/new/ の時と同じ ID・パスワードで入れる |
| ⑤ | https://duct-noda.com/contact/ から1回送信 | 担当の方と、入れたアドレスにメールが届く |
| ⑥ | AI 相談のキーを入れている場合：右下の「AIに相談」 | 答えが返ってくる |

どれかがおかしい時は、その画面の写真を送ってください。すぐに直せない時は B-7 で元に戻します。

### B-5. Google への届け出（10分。切り替えの当日か翌日）

1. Google サーチコンソール（https://search.google.com/search-console ）を開き、duct-noda.com を選ぶ
2. 左の「サイトマップ」で、`sitemap.xml` を入れて「送信」
   - 旧サイトのサイトマップ（`wp-sitemap.xml` など）が並んでいたら、その行の「︙」から削除する
3. 左の「URL 検査」に https://duct-noda.com/ を入れ、「インデックス登録をリクエスト」を押す

検索結果が新しいページに入れ替わるまで、数日〜数週間かかります。その間、旧サイトのアドレスで来た人は、新しいページへ自動で移ります。

### B-6. メールが迷惑メールに入る時

お問い合わせのメール（送り主 `noreply@duct-noda.com`）が、担当の方やお客様の迷惑メールのフォルダに入る時は、ドメインの「SPF」という設定が足りないことが多いです。

1. ドメインを管理している画面（コアサーバー／バリュードメインの「DNS設定」など）の写真を私に送ってください
2. 書き足す1行（`v=spf1` で始まる行）を、Boss のサーバーに合わせてお伝えします

/new/ での確認ではメールが届いているので、たいていは何もしなくて大丈夫です。

### B-7. うまくいかない時に元へ戻す（5分）

1. `public_html` の中に、新しいフォルダ `new` を作る
2. B-3 で移したもの（`app`、`assets`、`media`、`migration`、`storage`、`vendor`、`.htaccess`、`index.php`、`robots.txt`）を、`public_html/new` へ移す
3. `duct-noda.com/wp-old` の中身を全部（`.htaccess` も含む）、`public_html` へ移す
4. https://duct-noda.com/ で旧サイトが出ることを確かめ、私に連絡してください

新しいサイトのデータ（施工事例・お問い合わせ）はデータベースに残っているので、直したあとに B-2 からやり直せます。

### B-8. 落ち着いたら（1か月ほどたって問題がなければ）

- `duct-noda.com/wp-old` フォルダを削除してよい
- コアサーバーの「データベース」で、旧 WordPress のデータベースを削除してよい（新しいサイトのデータベースは消さないでください。名前は /new/ の最初の設定で入れたものです）
- WordPress の管理画面は無くなるので、WordPress の更新のお知らせなどは届かなくなります

## 制作側向けメモ

- 一式の作り方：`php tools/export-seed.php`（手元のデータベースから `migration/seed.sql`）→ `sh tools/build-package.sh`（`dist/upload/` に 90MB ごとに分けた `noda-site-n-of-N.zip` と `install.php`。1つの大きな zip だと送る途中で切れやすいため分けている）
- zip の中は「公開フォルダの中に app/ などを置く」形。`index.php` が `../app/` になければ `./app/` を読む。`app/ storage/ vendor/ migration/` はそれぞれの `.htaccess`（Require all denied）と公開フォルダの `.htaccess` の両方で閉じている
- `base_url` は `'auto'`（`SCRIPT_NAME` のフォルダから決める）。/new/ から本番の場所へ移しても書き換え不要
- 最初の設定（`/admin/setup.php`）：`app/config.php` が無ければデータベースの情報を聞いて作る → `schema.sql` → cases が空なら `seed.sql` を取り込む → 管理者登録 → `setup.php.done` に名前を変えて無効化。データベースの場所は localhost・127.0.0.1・*.coreserver.jp だけ受け付ける
- 試験用の場所の印（`noindex => true`）がある間は、`X-Robots-Tag` と meta robots で検索に載せず、Google タグマネージャーも読み込まない
- 置いた後の手直し：`sh tools/build-update.sh <前に渡したコミット>` で、変わったファイルだけの `noda-site-1-of-1.zip` と `install.php` を作る。ボスは2つを `new` に上げて install.php を開くだけ（設定・データベース・上げた写真はそのまま）
- 直した一式の渡し方（全部入れ直す時）：zip を作り直して同じ手順4〜5で上書きすれば、設定ファイル・データベース・管理画面で上げた写真はそのまま残る（setup.php が戻っても、管理者がいれば何もせず無効化される）
- 手元の Apache（`/srv/wp` を WordPress の場所に見立て、`/srv/wp/new/` に置く）で、install.php → 最初の設定 → 投稿・編集・削除 → フォームまで確認済み（2026-10-22）
- 本番切り替え（B）は、手元の Apache で WordPress の場所（/srv/wp）に見立てて、移す→確かめる→元に戻す、まで通した（2026-10-22）。`noindex` は `site_noindex()` で、`base_url` が `/` の時は設定にかかわらず外れる。`wp-content/` の `.php` は公開フォルダの `.htaccess` で 403
- 2回目以降の手直しでは、install.php を別の名前（kousin2.php など）に変えて開く。コアサーバー（LiteSpeed）は、一度消えた同じ名前のファイルをしばらく「無い」扱いにすることがある
